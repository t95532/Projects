# Video Studio — Local Render Engine (starter)

This folder is an **optional Windows-side rendering service** for the Video Studio PWA.

## What it does

- Accepts an original video, translated SRT, and already-generated dubbed WAV.
- Burns subtitles into the video.
- Replaces the original audio with the dubbed voice.
- Optionally mixes in a supplied vocals-removed accompaniment track (music/effects).

## What it does NOT do yet

This is a rendering foundation, **not the complete AI dubbing pipeline**. It does not itself:
- transcribe speech,
- translate Telugu/Hindi/English,
- generate a dubbed voice,
- separate dialogue from background music/effects.

Those assets must be generated by a separate ASR / translation / TTS / source-separation workflow before calling `/render`. Background music preservation is only possible when a suitable vocals-removed accompaniment stem is provided. It cannot reliably recover music from a mixed original audio track by itself.

## Windows setup

1. Install Python 3.11+.
2. Install FFmpeg and ensure both `ffmpeg` and `ffprobe` are available in PATH. The FFmpeg build must include the `subtitles` (libass) filter.
3. Extract/commit this folder into your repository at `docs/engine/`.
4. Double-click `START_ENGINE_WINDOWS.bat`.
5. Confirm `http://127.0.0.1:8765/health` returns JSON with `"status":"ok"`.

The service listens on port 8765 and binds to `0.0.0.0` so a phone on the same trusted Wi-Fi can reach the Windows PC using its LAN IP, e.g. `http://192.168.1.10:8765`. Allow Python through Windows Firewall only on a private network. Do not expose this service to the public internet.

## API

`GET /health`

`POST /render` as multipart form data:
- `video`: original video file
- `dubbed_audio`: final dubbed speech WAV
- `subtitles`: translated `.srt`
- `preserve_background`: `true` or `false`
- `accompaniment_audio`: optional vocals-removed background WAV; required when `preserve_background=true`

The response is a downloadable MP4.

## Important frontend integration note

The current GitHub Pages frontend is a static PWA. Uploading this folder alone does **not** automatically connect its UI to this service. The frontend must explicitly send the selected files to `http://127.0.0.1:8765/render` on Windows, or to the Windows PC's LAN address when accessed from a phone. Browsers may block mixed-content requests from HTTPS GitHub Pages to HTTP local/LAN endpoints; this needs a secure local bridge or a browser-compatible deployment strategy before mobile use.

## Safety and privacy

The engine processes uploaded files locally on the Windows computer. It has no authentication and is intended only for local testing on a trusted device/network. Do not port-forward it or expose it publicly.
